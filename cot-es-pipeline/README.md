# COT Report → ES: гайд по данным и первому срезу тестов

Цель: проверить, меняет ли положение Leveraged Funds в COT-отчёте распределение недельных и понедельничных исходов по ES. Никакой мифологии: одна переменная, восемь таблиц, критерии прохода заданы заранее.

Тесты идут прямо здесь, в этой папке, в Claude Code. Ты вводишь команды из этого файла и читаешь вывод. Код пишет и чинит Claude.

---

## 0. Что тестируем (зафиксировано, не менять по ходу)

| Параметр | Значение |
|---|---|
| Отчёт | CFTC, Traders in Financial Futures (TFF), **Futures Only** |
| Инструмент | **S&P 500 Consolidated** (SP + ES + MES одной строкой) |
| Группа | Leveraged Funds (основная), Asset Managers (второй прогон) |
| Метрика | Net = Long − Short, COT Index Уильямса, окно **52 недели** |
| Состояния | Low ≤ 20 / Mid / High ≥ 80. Второй прогон: 10/90 |
| Выравнивание | срез вторника T → публикация пятница T+3 → применяется к неделе с понедельника T+6 |
| Исходы 1.1 / 1.2 | ход недели и ход понедельника в %, бакеты = квинтили по всей истории |
| Исходы 2.1 / 2.2 | распределение типов открытия и типов дня (следующий этап) |
| Сравнение | Low и High отдельно против Mid |
| Исключения | недели до 2011, неполные недели, ролловые недели (третья пятница мар/июн/сен/дек + предшествующая), отчёты с задержкой (шатдауны) |
| Проход | n ≥ 30 недель в состоянии, разница с Mid ≥ 10 п.п. в бакете, тот же знак на 20/80 и 10/90 |

Формула индекса:

```
Net_t   = Long_t − Short_t
Index_t = (Net_t − min(Net за 52 нед.)) / (max(Net за 52 нед.) − min(Net за 52 нед.)) × 100
```

## 2. COT из CFTC

### Где это на сайте

cftc.gov → Market Reports → Commitments of Traders → **Historical Compressed**
(https://www.cftc.gov/MarketReports/CommitmentsofTraders/HistoricalCompressed/index.htm)

На странице несколько блоков. Нужен ровно один: **«Traders in Financial Futures ; Futures Only Reports»**. В нём по одному zip на год, в двух форматах: txt (CSV) и xls. Берём txt.

Прямые ссылки (год подставить):

```
https://www.cftc.gov/files/dea/history/fut_fin_txt_2026.zip
https://www.cftc.gov/files/dea/history/fut_fin_txt_2025.zip
…
https://www.cftc.gov/files/dea/history/fut_fin_txt_2010.zip
```

Остальные блоки пока не нужны:
- **Legacy** (`deacot…`): группы Commercials / Non-commercials. Понадобится, только если захочешь Commercial Index «по Уильямсу».
- **Disaggregated** (`fut_disagg…`): товарные рынки, ES там нет.
- **Futures-and-Options Combined** (`com_fin…`): те же TFF, но с опционами. Мы заморозили Futures Only.
- **Supplemental**: сельхоз, не нужен.

### Что внутри файла

CSV с заголовком, 87 колонок, все финансовые фьючерсы за год, одна строка на инструмент на неделю. Нужные колонки:

| Колонка | Что это |
|---|---|
| `Market_and_Exchange_Names` | название, ищем `S&P 500 Consolidated - CHICAGO MERCANTILE EXCHANGE` |
| `As_of_Date_In_Form_YYMMDD` | дата среза (вторник) |
| `Open_Interest_All` | открытый интерес |
| `Lev_Money_Positions_Long_All` / `_Short_All` | Leveraged Funds |
| `Asset_Mgr_Positions_Long_All` / `_Short_All` | Asset Managers |
| `Dealer_Positions_Long_All` / `_Short_All` | Dealers |
| `Contract_Units` | единица измерения (см. ловушку ниже) |

`_Spread_All` не трогаем. Строк по S&P 500 в файле несколько (E-mini, Micro, дивидендные индексы). Нам нужна только Consolidated.

### Автоматически

```bash
python3 scripts/01_download_cot.py
```

Качает 2010–2026 и архив 2006–2016 в `data/cot/`. Уже скачанные годы пропускает, текущий год перекачивает.

Если скачивание не прошло (сайт CFTC иногда режет скрипты), скачай zip руками со страницы, распакуй, положи `.txt` в `data/cot/` с любыми именами.

### Индекс и состояния

```bash
python3 scripts/02_cot_index.py
```

Выход: `data/derived/cot_states.csv`, одна строка на отчёт. Колонки: `report_date`, `apply_week_monday`, флаги `is_roll_week` / `delayed_release`, позиции трёх групп, `*_net`, `*_net_pct_oi`, `lf_idx52`, `am_idx52`, состояния `*_state_2080` / `*_state_1090`.

Что проверить в выводе:
- строка Consolidated найдена и покрывает все годы;
- в Low + High попадает порядка 25–30 % недель на 20/80 и 15 % на 10/90;
- первые 52 отчёта без индекса (разгон окна), это нормально.

### Что уже известно по данным (проверено 16.09.2026)

- Consolidated в TFF существует **с 15 июня 2010**. Архив 2006–2016 старше не даёт. Значит индекс 52w доступен с июня 2011, и «исходы с 2011» фактически означают «с середины 2011».
- **Ловушка с единицей.** До 2 мая 2023 Consolidated приведён к полноразмерному SP (`S&P 500 INDEX X $250`), после — к E-mini (`X $50`). В сырых числах все позиции и OI 2 мая 2023 прыгают в 5 раз. Скрипт 02 умножает строки в единицах $250 на 5, чтобы всё было в ES-эквиваленте. Без этого индекс на год после мая 2023 был бы мусором. Net в % от OI это не затрагивает.
- 8 срезов пришлись на понедельник (праздничные недели). Скрипт всё равно берёт следующий понедельник после публикации.
- 14 отчётов вышли с задержкой из-за шатдаунов (2013, 2018–19, 2025). Помечены `delayed_release=True`, из тестов исключаются, не интерполируются.
- Ролловых недель ~130 из 848.

## 3. OHLC по ES

### Почему минутки, а не дневки

Дневной бар из любого источника — это полные сутки Globex (18:00 → 17:00 NY). Нам нужны **RTH-открытие 09:30 и RTH-закрытие 16:00 New York**, а потом ещё 30-минутные бары для Market Profile. Всё это режется из минуток одним скриптом, поэтому качаем один раз минутки и больше к источнику не возвращаемся.

### Databento (основной источник)

| Параметр | Значение |
|---|---|
| Датасет | `GLBX.MDP3` (CME Globex, история с июня 2010) |
| Символ | `ES.v.0` — континуальный контракт, фронт по объёму |
| Схема | `ohlcv-1m` |
| Период | 2010-06-06 → сегодня |
| Время | UTC в файле, скрипт переводит в New York |

Ролл континуального символа происходит внутри ролловой недели, а ролловые недели из исходов исключены, поэтому фантомных гэпов внутри тестовой недели нет. Бэк-адъюстировать ряд не нужно: все ходы считаются внутри одной недели по одному контракту.

Ключ: в Databento → Settings → API keys. Скопируй `.env.example` в `.env` и вставь ключ:

```bash
cp .env.example .env
```

Сначала оценка стоимости (ничего не списывает):

```bash
python3 scripts/03_download_es.py
```

Потом само скачивание (ожидай единицы долларов за весь период):

```bash
python3 scripts/03_download_es.py --confirm
```

Файлы по годам в `data/es/es_1m_YYYY.parquet`. Повторный запуск докачивает только текущий год.

### Если Databento нет

Для тестов 1.1 / 1.2 подойдёт любой минутный ряд ES с UTC-меткой времени и колонками `ts_event, open, high, low, close, volume`:

```bash
python3 scripts/04_build_daily.py --csv путь/к/minutes.csv
```

Дневной RTH-ряд от брокера тоже сработает для 1.1 / 1.2, но для Market Profile (этап 5) без 30-минуток не обойтись.

### Сборка дневок и недель

```bash
python3 scripts/04_build_daily.py
```

Выход:
- `data/derived/es_daily_rth.csv`: RTH open/high/low/close по дням, число баров, время первого и последнего бара, флаги `half_day` (закрытие раньше 16:00) и `suspicious` (пропуски данных).
- `data/derived/es_weekly_rth.csv`: `week_open` (пн 09:30), `week_close` (пт 16:00), `week_move_pct`, `mon_open` / `mon_close` / `mon_move_pct`, флаг `full_week` (ровно 5 дней, без укороченных, начинается в пн и заканчивается в пт).

Что проверить: `first_bar` = 09:30 и `last_bar` = 15:59 почти везде, укороченных дней 2–3 в год, подозрительных ноль. Сверь 2–3 даты с графиком.

## 4. Тесты 1.1 и 1.2

```bash
python3 scripts/05_test_pa.py
```

Второй прогон по Asset Managers:

```bash
python3 scripts/05_test_pa.py --group am
```

Выход в консоль и в `data/derived/results_pa_lf.md`. Сначала воронка (сколько недель отсеялось на каждом фильтре), потом для каждого теста и порога таблица 3×5:

```
| state | n   | Q1 (сильно вниз) | Q2 | Q3 (около 0) | Q4 | Q5 (сильно вверх) | mean % | median % | P(up) |
| Low   | 106 | 17.0 | 24.5 | 15.1 | 21.7 | 21.7 | ...
| Mid   | 466 | 21.7 | 19.3 | 21.0 | 18.2 | 19.7 | ...
| High  |  80 | 15.0 | 17.5 | 20.0 | 27.5 | 20.0 | ...
```

Как читать:
- Границы квинтилей посчитаны по всем неделям вместе, поэтому Mid должен быть близок к 20/20/20/20/20. Если нет, что-то сломано в данных.
- Ниже идёт таблица «разница с Mid в п.п.» и список ячеек, где |разница| ≥ 10.
- Результат есть только если ячейка проходит на **обоих** порогах с тем же знаком и n ≥ 30.

Калибровка шума: на синтетических случайных минутках этот же скрипт при пороге 10/90 (n ≈ 50) выдал две ячейки с разницей +10 и +11 п.п. Это норма для выборки такого размера. Поэтому одиночная ячейка на 10/90 без подтверждения на 20/80 ничего не значит.

Если ничего не прошло: инструмент на уровне «уровень позиционирования LF» закрыт. Следующий кандидат по прошлому обсуждению: поток (изменение Net за 4 недели в % от OI) и изменение OI. Это отдельная переменная, а не поправка к этой.

Если что-то прошло: переходим к этапу 5 и к разрезу по дню недели, только после него.

## 7. Workspace

`../workspace/` это общее пространство тестов по всем инструментам (COT, Market Profile, Footprint). Принцип: **папка = сайт**. Каждая папка превращается в `index.html` рядом со своими исходниками, имена папок становятся хлебными крошками наверху страницы (`Тесты / COT Report / Price Action-Based / 1.1 Ход недели`).

```
workspace/
  build.py                 генератор, stdlib
  index.md                 корневая страница
  assets/style.css         общий стиль
  assets/renderers/*.js    интерактивные блоки результатов
  COT Report/
    index.md
    Price Action-Based/
      index.md
      1.1 Ход недели/           test.md + results.json
      1.2 Ход понедельника/     test.md + results.json
      Границы индекса/          test.md + results.json
      Данные и метод/           test.md
  Market Profile/index.md  раздел зарезервирован
  Footprint/index.md       раздел зарезервирован
```

Папка с `test.md` это тест, без него раздел (`index.md` необязателен). Схема `test.md`: frontmatter с ключами `id, title, status, created, updated, instrument, renderer, test, variables, verdict, verdict_note, source`, затем разделы `## Идея`, `## Переменные`, `## Метод и исключения`, `## Результаты`, `## Вердикт`, `## Журнал`. Ключ `renderer` выбирает интерактивный блок в разделе «Результаты»: `markdown` (ничего), `cot_pa_tables` (нужен `test: week|mon` и results.json от шага 6), `cot_yesno` (results.json от шага 8).

Добавить новый тест: создать папку в нужном разделе, скопировать `test.md` любого готового теста, заполнить, при необходимости написать экспорт `results.json` и новый рендерер в `assets/renderers/` с регистрацией в `RENDERERS` внутри `build.py`, запустить `python3 ../workspace/build.py`.

Документ-выжимка по ресерчу собирается из `test.md` (паспорт, вердикт, журнал), поэтому всё, что важно для истории, пишется туда, а не в HTML.
